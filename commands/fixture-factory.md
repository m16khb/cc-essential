# Fixture Factory

DTO/Entity 타입을 분석하여 타입-안전한 테스트 픽스처를 자동 생성한다.

## 아규먼트 처리

| 아규먼트 | 설명 | 기본값 |
|----------|------|--------|
| `<type-name>` | 픽스처 대상 타입명 (예: User, CreateUserDto) | 필수 |
| `--count=N` | 정적 픽스처 개수 | 3 |
| `--locale=ko` | 데이터 로케일 | ko |
| `--from=<path>` | 디렉토리 내 모든 Entity/DTO 처리 | - |

## 실행 단계

### 1. 타입 파일 탐색

```bash
# 타입명으로 파일 찾기
find . -name "*.ts" -type f | xargs grep -l "export class {type-name}"
```

### 2. 타입 분석

Read 도구로 타입 정의를 분석:

```typescript
// 분석 대상
@Entity()
export class User {
  @PrimaryColumn()
  id: string;

  @Column()
  email: string;

  @Column()
  name: string;

  @Column({ type: 'enum', enum: UserRole, default: UserRole.USER })
  role: UserRole;

  @Column({ nullable: true })
  phone?: string;

  @CreateDateColumn()
  createdAt: Date;

  @UpdateDateColumn()
  updatedAt: Date;
}
```

추출 항목:
- 필드명, 타입
- 필수/선택 여부
- 기본값
- enum 타입
- 관계 (OneToMany, ManyToOne 등)

### 3. 픽스처 파일 생성

**출력 경로:** `test/fixtures/{type-name}.fixture.ts`

```typescript
/**
 * {TypeName} 테스트 픽스처
 *
 * @generated by cc-essential fixture-factory
 * @see {source-file-path}
 */

import { {TypeName}, {EnumTypes} } from '@/path/to/entity';

// ============================================================
// 정적 픽스처 - 예측 가능한 테스트용
// ============================================================

export const {typeName}Fixtures: {TypeName}[] = [
  {
    id: '{prefix}_test001',
    email: 'kim.minjun@example.com',
    name: '김민준',
    role: {EnumType}.USER,
    phone: '010-1234-5678',
    createdAt: new Date('2025-01-01T00:00:00Z'),
    updatedAt: new Date('2025-01-01T00:00:00Z'),
  },
  {
    id: '{prefix}_test002',
    email: 'lee.soyeon@example.com',
    name: '이소연',
    role: {EnumType}.ADMIN,
    phone: '010-2345-6789',
    createdAt: new Date('2025-01-02T00:00:00Z'),
    updatedAt: new Date('2025-01-02T00:00:00Z'),
  },
  // ... count개 만큼 생성
];

// ============================================================
// 동적 팩토리 - 커스텀 오버라이드용
// ============================================================

let fixtureCounter = 0;

export const create{TypeName}Fixture = (
  overrides?: Partial<{TypeName}>,
): {TypeName} => {
  fixtureCounter++;
  return {
    id: `{prefix}_${Date.now()}_${fixtureCounter}`,
    email: `test${fixtureCounter}@example.com`,
    name: `테스트유저${fixtureCounter}`,
    role: {EnumType}.USER,
    phone: null,
    createdAt: new Date(),
    updatedAt: new Date(),
    ...overrides,
  };
};

// ============================================================
// 특수 케이스 픽스처
// ============================================================

/** 최소 필수 필드만 포함 */
export const minimal{TypeName}Fixture: Partial<{TypeName}> = {
  id: '{prefix}_minimal',
  email: 'minimal@example.com',
  name: '최소',
};

/** 모든 선택 필드가 null인 케이스 */
export const nullable{TypeName}Fixture: {TypeName} = {
  id: '{prefix}_nullable',
  email: 'nullable@example.com',
  name: '널러블',
  role: {EnumType}.USER,
  phone: null,
  createdAt: new Date(),
  updatedAt: new Date(),
};

// ============================================================
// 헬퍼 함수
// ============================================================

/** 여러 개의 픽스처 생성 */
export const create{TypeName}Fixtures = (
  count: number,
  overrides?: Partial<{TypeName}>,
): {TypeName}[] => {
  return Array.from({ length: count }, () =>
    create{TypeName}Fixture(overrides)
  );
};

/** 픽스처 카운터 리셋 (테스트 간 격리용) */
export const reset{TypeName}FixtureCounter = (): void => {
  fixtureCounter = 0;
};
```

### 4. 데이터 생성 규칙

| 필드 타입 | 생성 규칙 (locale=ko) |
|----------|----------------------|
| `string` (email) | 한글이름@example.com |
| `string` (name) | 한국 이름 (김민준, 이소연 등) |
| `string` (phone) | 010-XXXX-XXXX |
| `string` (id) | prefix_nanoid |
| `number` | 순차 증가 또는 랜덤 |
| `boolean` | true/false 교대 |
| `Date` | 순차적 날짜 (하루씩 증가) |
| `enum` | 가능한 값 순환 |
| `array` | 빈 배열 또는 1-2개 요소 |
| `object` | 중첩 픽스처 호출 |

### 5. 관계 데이터 처리

OneToMany, ManyToOne 관계 감지 시:

```typescript
/** 관계 데이터 포함 팩토리 */
export const create{TypeName}With{RelationName}Fixture = (
  {typeName}Overrides?: Partial<{TypeName}>,
  {relationName}Count = 3,
): { {typeName}: {TypeName}; {relationName}: {RelationType}[] } => {
  const {typeName} = create{TypeName}Fixture({typeName}Overrides);
  const {relationName} = Array.from({ length: {relationName}Count }, (_, i) =>
    create{RelationType}Fixture({
      {foreignKey}: {typeName}.id,
      // 순차 데이터
    }),
  );
  return { {typeName}, {relationName} };
};
```

### 6. 결과 출력

```
✅ 픽스처 생성 완료

파일: test/fixtures/user.fixture.ts

생성된 내용:
├── userFixtures (정적 픽스처 3개)
├── createUserFixture (동적 팩토리)
├── minimalUserFixture (최소 필드)
├── nullableUserFixture (null 케이스)
├── createUserFixtures (배치 생성)
├── resetUserFixtureCounter (리셋 함수)
└── createUserWithPostsFixture (관계 포함)

import 예시:
import { userFixtures, createUserFixture } from '@/test/fixtures/user.fixture';
```

## 디렉토리 일괄 처리

```bash
/fixture-factory --from src/modules/user/entities/
```

디렉토리 내 모든 Entity 파일에 대해 픽스처 생성:
- `user.entity.ts` → `user.fixture.ts`
- `profile.entity.ts` → `profile.fixture.ts`

## 주의사항

- 기존 픽스처 파일이 있으면 덮어쓰지 않고 경고
- circular dependency 관계는 단방향만 생성
- 실제 DB 연결 불필요 (순수 객체 생성)
- 민감 정보 (비밀번호 등)는 placeholder 사용
